# Splitting an issue

Split only at a logical seam: a capability a separate, reusable component (its own package or library with its own tests) gains, whole and proved by those tests, before an application uses it; or an outcome the owner asked to deliver separately. Size, line count, estimate and a port, adapter, wiring or UI layer inside one feature are never seams; an issue an agent can deliver in one go stays one PR. Fold a slice that delivers nothing on its own into the change that uses it. An issue found to need several PRs at such a seam is split into an epic with one-PR sub-issues, never sliced by `Part of` PRs. Its own authority approves the epic. First set `type:epic`, drop its lane and rewrite its body in the epic form, so an interrupted split leaves an epic to slice, not a story to rebuild. Then create its one-PR sub-issues as for an epic slice, each packet within the issue's packet (the run's push checks that copy), with blocked-by links where order matters. A run builds the first sub-issue under its hold, and the epic closes through its close check.
