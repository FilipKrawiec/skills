# Splitting an issue

Keep related fixes, implementation, tests and docs in one bounded, independently reviewable issue and PR when they can ship together, saving repeated agent, review and coordination costs. Split for a concrete independent outcome, a meaningful dependency (such as a separately useful prerequisite), an authority boundary or a delivery constraint. Record the reason; size, estimate or layer alone is not one. Keep acceptance, quality, independent review and owner-authority gates for every resulting issue and PR. Fold a slice that delivers nothing on its own into the change that uses it. An issue found to need several PRs at such a seam is split into sibling stories or bugs under the same epic, never a nested epic and never sliced by `Part of` PRs. The planner splits on this rule alone; the owner never approves a split of unstarted work. Narrow the issue to its first outcome, then create each other outcome as a sibling with `--parent` the same epic, each packet within the issue's packet (the run's push checks that copy), with blocked-by links where order matters. An issue under no epic is narrowed only; the planner hands back `blocked` for the rest, which needs an epic first.

## Consolidate unstarted duplicates

The planner (or `refine`) merges unstarted issues that share an outcome, never a started issue, one with an open PR, issues in different epics without a shared outcome, or anything under `lane:owner`. Carry every outcome, criterion, dependency, decision and milestone into one canonical issue N, comment where each went, append `<!-- workflow:consolidated-into N -->` to each other body and close it as not planned. A dependency on a closed one then follows N, never an owner step. Only a started or `lane:owner` duplicate needs owner authority. `drive` sends overlapping unstarted issues (shared epic, overlapping `scope` paths) to the planner before it starts one, and reports what merged.
